# Hook Authoring

- **POSIX ERE only in hook scripts** — macOS `grep -E` does not support `\s`, `\d`, `\b`, or other PCRE shortcuts. Use literal spaces, `[0-9]`, `[[:space:]]`. Use `grep -qE -- 'pattern'` when patterns start with `-`.
- **Test hooks before registering** — `echo '{"tool_input":{"command":"..."}}' | ~/.claude/hooks/hook-name.sh` to verify output and exit code.
- **A test payload for a command-matching hook contains that hook's own trigger, so the live hook fires on the test harness** — the `echo '{…}' | hook.sh` form above puts the pattern on a real Bash command line, which is exactly where every registered `PreToolUse` hook reads from. The harness call is intercepted before the hook under test ever runs, and the result looks like a bug in the hook rather than an artifact of how it was invoked. Keep the payload off the command line: build it inside a script file and run the file, or assemble the trigger from concatenated fragments in a variable. The hook under test still receives the complete payload on stdin — only the harness's own command line changes, so test fidelity is unaffected.
- **`gh api` defaults to GET, so a read carries no `-X` at all** — a guard that keys its allow on an explicit `-X GET` blocks every ordinary read, because the shape it demands is the one nobody types. Detect the *write* (`-X POST|PATCH|PUT`, or a body flag) and treat the absence of a method as a read.
- **Scope a flag test to the segment that owns it** — a Bash tool call is frequently a whole pipeline or `&&` chain, so testing the entire command string for a flag attributes any neighbour's flags to the command you meant to inspect. `rm -f`, `grep -F`, `cp -f`, `sort -f` and `ls -F` all supply a bare `-f`/`-F`, which is enough to make a plain `gh api` read look like it carries a request body. Split on unquoted separators with [`_lib/split-cmd-segments.pl`](../hooks/_lib/split-cmd-segments.pl) and run the test against the matching segment only. The split must be quote-aware in both directions: an unquoted `|` genuinely separates commands, while a `|` inside `--jq '.[] | length'` does not, and treating the latter as a separator truncates the segment before its real flags. When the helper is unavailable, fall back to the whole command — over-firing a checklist is the safe way to be wrong. The helper emits **NUL-delimited** segments, not one per line, because a segment can itself contain newlines whenever a quoted argument spans them: read it with `while IFS= read -r -d ''`. A newline-delimited read of the same stream silently keeps only the line that names the command and discards the rest of the segment, so a multi-line body — which every real review payload has — never reaches the test. For the same reason, anchor a `^`-rooted invocation pattern to the segment's own *first line* (`${seg%%$'\n'*}`); a line-oriented `grep -E '^cmd'` also matches line 2 of a quoted document, promoting prose *about* a command into a call to it.
- **Keep utility scripts in a dedicated dir** (e.g. `~/.claude/scripts/`) — referenced by hooks or invoked directly. Sharing one helper across hooks beats duplicating logic per hook.
- **Session analytics** — Mine `~/.claude/projects/*/*.jsonl` (excluding `*/subagents/*`) to find tool-call waste. Run periodically. See `session-analytics-guide.md` for queries.
